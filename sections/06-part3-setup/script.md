## Step 3：核心概念 — Terminal-native AI（5 min）

[切換投影片 — Terminal-native AI]

Claude Code 跟你之前用過的 AI 有一個根本性的差異：它是 terminal-native 的。

這是什麼意思？三件事：

[切換投影片 — 三大能力]

**第一，它能讀檔案。** 你電腦上的檔案，它可以直接讀。不需要你複製貼上。

**第二，它能寫檔案。** 它可以幫你建立新檔案、修改現有檔案。直接寫進你的電腦。

**第三，它能跑指令。** 它可以在你的 Terminal 裡執行命令——安裝套件、跑測試、開伺服器。

[停頓]

[看向觀眾]

你們想一下——ChatGPT 能做這些嗎？你在瀏覽器裡跟 ChatGPT 聊天，它能讀到你桌面上的檔案嗎？不行。它能幫你建立一個檔案存到你的電腦裡嗎？不行。它能在你的電腦上跑一個程式嗎？不行。

Claude Code 可以。因為它不在瀏覽器裡——它就在你的 Terminal 裡，跟你的電腦是直接連通的。

這就是為什麼它叫 Agent，而不只是 Chatbot。回想一下 Part 1 的比喻：LLM 是大腦，Agent 是有手有腳的員工。那雙手、那雙腳，就是讀檔案、寫檔案、跑指令的能力。

## Step 4：Permission Model（4 min）

[切換投影片 — Permission Model]

但是你們有沒有想過一個問題？

如果 Claude Code 能讀你的檔案、寫你的檔案、在你電腦上跑任何指令——那它會不會失控？會不會亂改你的東西？會不會刪掉你的碩論？

[停頓]

這是一個非常好的問題。答案是：不會，因為它有一個安全機制，叫做 Permission Model。

等一下你做練習的時候就會看到——每當 Claude Code 要做一個「有影響力」的動作，比如建立一個新檔案、修改一個檔案、執行一個指令，它都會先問你：

「Can I do this?」

然後你看一下它要做什麼，覺得 OK，你就按 Y 同意。覺得不對，按 N 拒絕。

[切換投影片 — 人機控制迴圈圖]

這個機制叫做 human-in-the-loop——人類始終在控制迴圈中。AI 提案，人類審批。AI 不會自己偷偷做事。

[停頓]

[看向觀眾]

這其實就是你們在管理課上學過的——delegation with oversight。你委派任務給下屬，但你保留最終的 approval 權。Claude Code 的設計哲學一模一樣：AI 是執行者，你是決策者。

所以不要怕。你永遠握著方向盤。它再聰明，也要經過你同意才能動手。

而且我建議你們在學習階段，先不要開啟自動允許。每次它問你的時候，花一秒鐘看一下它要做什麼——這也是最好的學習機會，你可以看到 AI 的思考過程：它拆解了什麼步驟、它打算用什麼方法。
