## 產品化流程（4 min）

[切換投影片：產品化流程圖]

我先給你一條路徑，非常簡單：

**Idea → Claude Code Prototype → Feasibility Assessment → Engineering Handoff → Production**

五個步驟。我們一個一個講。

**第一步，Idea。** 這不用解釋吧？你的老闆、你的客戶、你自己洗澡的時候想到的東西。每個人都有 idea，idea 不值錢——值錢的是你能不能快速驗證它。

**第二步，Claude Code Prototype。** 這就是你今天學的。你有一個 idea，你丟給 Claude Code，20 分鐘做出一個能動的東西。不是 PPT，不是線框圖——是一個真的能跑、能點、能看到結果的東西。

[停頓]

這步為什麼重要？因為傳統的流程是這樣的：idea → 寫 spec → 開會討論 → 排期 → 工程師花兩週做出 v1 → 老闆看了說「不是這個意思」→ 打掉重來。整個循環可能要一個月。

現在呢？你 20 分鐘做出 prototype，走到老闆面前說「你看，是不是這個意思？」老闆說不是——好，你回去改 prompt，再 20 分鐘。一個下午你可以迭代三四版。

小紅書上有人說「AI 1 分鐘畫好產品原型，PM 救星」——1 分鐘可能稍微誇張了一點，但那個精神是對的。**快速驗證，快速失敗，快速調整。** 這個循環越快，你浪費的資源越少。

**第三步，Feasibility Assessment。** Prototype 做出來了，老闆也點頭了——但這東西真的能做成產品嗎？技術上可行嗎？成本合理嗎？資料安全過得了嗎？這些問題是你作為 Technology Manager 要回答的，不是 AI 幫你回答的。

**第四步，Engineering Handoff。** 你把驗證過的 prototype 交給工程團隊。注意——你交的不是 Claude Code 生成的 code。那個 code 是 prototype 品質，不是 production 品質。你交的是一個**可以跑的 demo + 明確的需求文件**。工程師看到能動的東西，理解速度比看 spec 快十倍。

**第五步，Production。** 工程團隊用他們的技術棧重新實作。但因為有了 prototype，需求溝通的來回減少了、方向性的錯誤減少了、整體開發時間壓縮了。

[看向觀眾]

所以你看到了嗎？Claude Code 在這條路徑上的角色不是「取代工程師」——它是**取代等待**。它讓你從「想到」到「看到」的時間從兩週變成兩小時。

## 進階概念（7 min）

[切換投影片：進階概念]

好，接下來我快速介紹四個進階概念。今天不會練習這些——但我要讓你知道它們的存在，這樣你回去之後想深入的時候知道往哪裡挖。

### 1. CLAUDE.md

[切換投影片：CLAUDE.md]

第一個概念叫 **CLAUDE.md**。

你還記得我們今天花了很多時間在講 prompt 怎麼寫嗎？Context、Constraints、Check。每次跟 AI 對話你都要重新交代一次背景——「我是做什麼的、我的專案架構是什麼、我喜歡什麼程式風格」。很煩。

CLAUDE.md 就是解決這個問題的。

它是一個 Markdown 檔案，放在你的專案根目錄。你把團隊的 coding style、架構決策、命名規範、重要的 context 全部寫進去。Claude Code 每次啟動的時候會自動讀這個檔案——它就像一份「新人 onboarding 文件」，但讀的人不是新人，是 AI。

[停頓]

這對團隊來說特別有價值。想像你的團隊有 5 個人都在用 Claude Code——如果沒有 CLAUDE.md，每個人給的 context 不一樣，AI 的輸出風格就不一樣。有了 CLAUDE.md，**團隊知識被結構化了**，AI 的行為就一致了。

你可以把它想成是「給 AI 看的 team wiki」。

### 2. Agentic Workflow

[切換投影片：Agentic Workflow]

第二個概念：**Agentic Workflow**。

今天你們用 Claude Code 的時候，基本上是一問一答——你給一個指令，AI 做一件事，你再給下一個指令。

但 Agent 真正厲害的地方，是你可以給它一個**目標**，讓它自己拆解步驟、自己執行。

比如你說：「幫我分析這個資料夾裡所有的 CSV，找出異常值，畫成圖表，然後寫一份摘要。」這不是一個步驟——這是四五個步驟。Agent 會自己決定先做什麼、後做什麼，中間遇到問題會自己調整。

這就是為什麼它叫 **Agent** 而不只是 chatbot。Chatbot 是你問一句它答一句。Agent 是你給一個任務，它自己跑完整個流程。

[看向觀眾]

不過回到我們前面講的——它每一步還是會問你 Allow。它是自主的，但不是失控的。你還是那個按「確認」按鈕的人。

### 3. Multi-file Editing

[切換投影片：Multi-file Editing]

第三個：**Multi-file Editing**——同時修改多個檔案。

這個對技術背景不深的同學來說可能比較抽象，但我舉個例子你就懂了。

假設你在做一個 web app。你想加一個新功能——比如「用戶可以上傳頭像」。這不是改一個檔案就能搞定的。你要改前端的介面、改後端的 API、改資料庫的 schema、可能還要加一個上傳的 component。四五個檔案。

傳統的 AI 工具——比如 ChatGPT——你一次只能貼一個檔案進去。你改了 A 檔案，但 B 檔案還是舊的，它們之間就對不上了。

Claude Code 因為是在你的專案目錄裡面跑的，它**看得到所有檔案**。你說「加一個頭像上傳功能」，它可以同時改五個檔案，而且保證它們之間是一致的。

這就是 IDE 內建 Agent 跟網頁版 chatbot 最大的差別。

### 4. Git Integration

[切換投影片：Git Integration]

最後一個：**Git Integration**——版本管理。

[互動] 在場有用過 Git 的嗎？舉手看看。

[動作：看舉手的人數]

OK，不管你有沒有用過，概念很簡單：Git 就是你的「無限後悔藥」。你做了一個改動，存一個版本。做了第二個改動，再存一個版本。如果第二個改動搞砸了——一鍵回到上一個版本。

Claude Code 把 Git 直接整合進來了。它每做一組修改，你都可以選擇存一個版本。這意味著你讓 AI 大膽嘗試、放手做——做壞了？回溯就好。

[停頓]

這解決了一個很真實的恐懼：很多人不敢讓 AI 動自己的 code，怕它搞壞。有了 Git Integration，你隨時可以回到任何一個「已知正確」的狀態。你的安全網就在那裡。
