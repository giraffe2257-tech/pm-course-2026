## 開場 + 規則（5 min）

[動作：確認學員都回座位了]

好，歡迎回來。接下來 50 分鐘是今天的重頭戲——你要自己動手了。

在我說規則之前，我先講一件事。我看到牛津有個博士生分享他每天用三個 AI 工具做研究——Claude 負責思考輔助，幫他篩文獻、理邏輯；Obsidian 負責知識積累；Copilot 負責跑數據。他說這三個工具串起來之後，他的研究效率翻了一倍。

你們在 KCL，離這個場景只有一步之遙。今天這 50 分鐘，就是讓你親手跨出那一步。

但我要先講一件事。

這 50 分鐘的目的**不是**讓你完成一個漂亮的作品。

[動作：停頓]

我再說一次——重點不是你的成品有多好看。

重點是你要親手跑過一次完整的循環：**下 prompt → 拿輸出 → 判斷要不要採納**。

這個循環，不管你今天做的是 literature review、問卷分析、還是會議紀錄，都是一樣的。場景只是包裝紙，那個循環才是你今天要學會的東西。

[動作：切換到場景列表投影片]

好，看一下你們有哪些場景可以選。我準備了五個學術場景：

**Scenario A — Literature Review 加速器** ⭐⭐⭐
批量處理 PDF 論文，自動提取研究問題、方法論、發現、限制，生成比較表。適合正在寫 lit review 的同學。時間需要 20 到 25 分鐘。小紅書上有個人分享了用 Claude 寫論文的五步流程——精讀、故事線打磨、段落寫作、語言潤色、反駁預演。今天我們用前兩步就好，不用全做。

**Scenario B — Group Project 會議追蹤** ⭐
把雜亂的會議紀錄變成結構化的 minutes + action item tracker。最簡單、最直覺、人人有感。15 到 20 分鐘。Dropbox 的高管分享過一個方法——開會前用 AI 模擬每個與會者的角色來預演，開完會用 AI 整理 action items。你們今天做後半段就好。

**Scenario C — 問卷數據快速分析** ⭐⭐⭐
100 份 CSV 問卷跑統計分析、畫圖表、寫 findings 初稿。想看 AI 寫程式的選這個。25 到 30 分鐘。有個用研經理分享說，他用 AI 跑問卷分析之後，分析週期從兩三天壓縮到半天，而且開放題的主題聚類效果特別好——這就是你們等一下會做的事。

**Scenario D — Reference 管理與格式轉換** ⭐⭐
散落的引用資料統一轉成 Harvard style，加上一致性檢查。15 到 20 分鐘。

**Scenario E — Dissertation 結構化寫作助手** ⭐⭐
大論文拆成小檔案，AI 當 writing coach 逐章 review。20 到 25 分鐘。有人用 Gemini 加 Claude 雙模型寫論文——Gemini 做資料收集，Claude 做結構設計和修訂。他的結論是：論文寫作的重點不在 AI 幫你寫了多少字，而在前期的結構設計和後期的修訂。

[動作：停頓]

## 選場景的建議（2 min）

不知道怎麼選？我給你幾個指標：

如果你是第一次用 AI、不太確定怎麼開始——選 **B（會議追蹤）**或 **D（Reference 管理）**。最不會卡住。

如果你正在寫論文、痛感最強——選 **A（Lit Review）**或 **E（Dissertation）**。

如果你想看 AI 寫 Python、跑分析——選 **C（問卷分析）**。這個最技術，但也最炫。

如果你最在意 academic integrity 的討論——**A** 和 **E** 的灰色地帶最多，等下可以好好聊。

還有一個原則：**選你下週真的會用到的那個。** 你下週最痛的事是什麼？選那個。不要選「看起來最酷」的，選「對你最有用」的。

## Academic Integrity 紅線（2 min）

[動作：切換到 Integrity 投影片]

在你們動手之前，我要把一條線劃清楚。

我先講一個真實案例。利茲大學有個學生，在學術聽證會上自己承認用 AI 寫論文——結果直接被開除。不是因為學校的 AI 檢測抓到他，是他自己在聽證會上講了。重點是什麼？他寫的那個 prompt 、跑出來的結果、他完全說不出「我為什麼做了這個判斷」。

**AI 是研究助理，不是作者。**

[動作：停頓]

什麼意思？

**可以做的事：**
- 讓 AI 整理、抽取、比較資訊——這是 productivity tool
- 讓 AI 改格式、找錯、檢查一致性——這等同 Zotero、Grammarly
- 讓 AI 生成分析腳本、跑統計——這是自動化工具

**不可以做的事：**
- 讓 AI 寫 critical analysis 然後當作你自己的論證
- 讓 AI 編造不存在的 reference
- 把 AI 的初稿一字不改交出去

判斷標準很簡單：你的 supervisor 看到你的成品，能不能說「這個 argument 是你想出來的」？如果 supervisor 問你「你為什麼做這個判斷？」你答得出來嗎？答不出來的，就是越線了。

每個場景的 README 裡面都有標注 academic integrity 的具體指引。做之前看一下。

## 分組 + 開始（3 min）

好，分組。3 到 4 人一組。跟你旁邊的人組就好，不用刻意打散。

每組選一個場景。如果同組的人意見不一——選最簡單的那個。你的第一次 AI 實作，成功比野心重要。

[動作：巡場確認每組選好了]

選好了嗎？好。打開你的 terminal，進到 `claude-code-workshop/exercises/` 資料夾，找到對應場景的 README.md。

先花 2 分鐘看 README，它告訴你：
1. 要做什麼
2. 建議的步驟
3. 範例 prompt
4. 預期的輸出是什麼

看完之後，用 CCC 框架寫你自己的 prompt，丟給 Claude Code。

**不要直接複製 README 裡的範例 prompt**——那個是參考，你要自己根據你的理解來寫。這就是練習。

開始吧。

## 實作巡場（33 min）

[動作：離開講台，開始在各組之間走動]

### 巡場指引（講師自用，不投影）

**巡場節奏：**
- 前 5 分鐘：確認每組都啟動了，有人在打 prompt
- 5-15 分鐘：重點看有沒有人卡住
- 15-25 分鐘：開始問組別「你們的第一個輸出怎麼樣？」引導他們做 Check
- 25-33 分鐘：提醒時間，讓他們準備 demo

**學員卡住時的標準回應：**

如果學員說「我不知道怎麼寫 prompt」：

> 好，我問你三個問題。第一，你要讓它做什麼——用一句白話講。第二，有什麼限制——格式、長度、什麼不能做。第三，你怎麼知道它做對了。把這三個答案串起來，就是你的 prompt。

（講師備註：Anthropic 官方的 Prompt 101 也是這個邏輯——任務描述、內容提供、詳細指令、示例、重要提醒五個模塊。跟 CCC 本質相同，只是切法不同。如果學員是做 Lit Review，可以提示他們先給 AI 一篇論文當示例，讓它看到你期望的提取格式。）

如果學員說「AI 寫得很爛 / 不是我要的」：

> 那我問你——你給了它什麼 Context？Constraints 呢？是 AI 爛，還是你的指令不夠清楚？我們來看看你的 prompt 哪裡可以加東西。

（講師備註：做問卷分析 (Scenario C) 的組特別容易遇到這個問題。常見的坑是直接把 CSV 丟進去說「分析一下」。建議引導他們分步走：先讓 AI 跑選擇題的頻率統計，確認數字對了，再讓它做開放題的主題聚類。一步一步驗證，不要一次丟全部。）

[動作：不要直接給學員答案，用反問引導他們自己改 prompt]

如果學員說「它一直問我 Allow」：

> 對，這是正常的。它每次要在你電腦上做事都會問你。你就看一下它要做什麼，覺得合理就按 Allow。如果看不懂它要做什麼——可以問它「你接下來打算做什麼？」

如果學員的 API key 或環境出問題：

> 不要讓他卡在技術問題上。直接讓他加入隔壁組，先看別人怎麼做。workshop 後再個別處理環境問題。

**中途提醒（大約 15 分鐘時）：**

[動作：拍手或提高音量引起注意]

大家暫停一下——你們現在應該已經拿到第一版輸出了。

我要你做一件事：**不要急著繼續。先看一下 AI 給你的東西。**

三個問題：
1. 這個輸出有沒有回答你的需求？
2. 裡面有沒有明顯錯誤？（數字對嗎？引用存在嗎？格式正確嗎？）
3. 你要採納、修改後採納、還是丟掉重來？

這就是第三個 C——Check。做了嗎？做了就繼續。

[動作：回到巡場]

**結束前 5 分鐘提醒：**

[動作：提高音量]

各位，還有 5 分鐘。不需要做完整個場景——我剛說了，重點不是做完，是你跑過了那個循環。

每組準備一下 demo：你們做了什麼、AI 給了什麼、你們決定採納還是丟掉，為什麼。每組 1 分鐘。

## Demo + 收尾（5 min）

[動作：回到講台]

好，時間到。每組 1 分鐘，告訴我們三件事：

1. 你選了哪個場景
2. AI 給你的輸出長什麼樣
3. **你為什麼決定採納或丟掉**——這是最重要的

誰先來？

[動作：讓每組簡短報告。如果有組太長了，友善打斷：「好，很棒，核心重點是什麼？」]

**報告結束後收網：**

好，大家做得很好。我想你們剛剛已經體會到了幾件事：

第一，**prompt 寫得越清楚，AI 做得越好**。有些組第一版的 prompt 太模糊，改了一版馬上效果就不一樣了。

第二，**AI 不是完美的**。它會漏東西、會格式不對、甚至可能會幻覺。所以 Check 那一步不是可選的，是必須的。

第三，**這個循環跟場景無關**。不管你做的是 lit review 還是會議紀錄，「下指令 → 拿結果 → 判斷」的模式是一樣的。你學會了這個模式，回去可以套用在任何場景上。

有人說得很好——用 Claude 寫論文有五步，但其中最關鍵的一步是「反駁預演」：你寫完之後，讓 AI 扮演審稿人，專門找你的邏輯漏洞。這就是 Check 的進階版。你不只是看「格式對不對」，而是讓 AI 幫你壓力測試你的論證。今天你們做了第一步，回去可以試試這一步。
