# Student Profile — 你們需要的三種能力

---

[承接上一段，語氣從開場轉為正題]

好，那我們現在來聊一個很重要的問題——你們到底為什麼要來上這門課？

[停頓]

我知道你們在想什麼。「我是念 Technology Management 的，不是 Computer Science。我幹嘛要學寫 code？」

對不對？有沒有人心裡是這樣想的？

[互動——等幾個人點頭或舉手]

很好，很誠實。我喜歡。

但我今天要告訴你們一件事——這門課，重點**真的不是**叫你們寫 code。

[切換投影片：三種能力卡片]

Technology Management 的核心是什麼？是**理解**科技、**評估**科技、**管理**科技。不是自己從零刻出一個系統。所以今天這個 workshop，我要幫你們建立三種能力。

---

**第一種：技術判斷力。**

什麼意思？就是當有人跟你說「這個用 AI 做不到」或者「這個 AI 一定能搞定」的時候，你有能力判斷——他講的是真的，還是在唬爛。

[停頓]

這個在業界超級重要。你未來當 PM、當產品負責人、當顧問，一定會遇到工程師跟你說「這個要做三個月」。你要有能力判斷：是真的要三個月，還是他只是不想做？

技術判斷力也包括 build vs buy 的決策。現在 AI 工具這麼多，什麼時候該自己建、什麼時候該買現成的、什麼時候用 AI 就能搞定？這是你們未來每天都要面對的問題。

---

**第二種：AI-augmented 生產力。**

[看向觀眾]

這個是今天的重頭戲。簡單講就是——用 AI 當你的加速器。

我舉個例子。以前你要做一個 prototype，可能要找工程師幫忙，排期兩個禮拜。現在呢？你自己跟 Claude Code 對話兩個小時，一個能跑的 prototype 就出來了。兩週變兩小時，這不是誇張，這是我們等一下要實際操作的事情。

最近小紅書上有個人分享，他沒有 developer 背景，花了三天就考過了 Anthropic 的 Claude Certified Architect。他自己都說「對於試圖轉型的非 developer 人員還是蠻有幫助的」。重點不是那張證書，重點是——技術的門檻正在被 AI 快速拉低。你們不需要四年 CS 訓練，就能做出有用的東西。

---

**第三種：跨域溝通。**

[切換投影片]

HBR 最近有篇文章講得很好——未來的管理者要從「指揮者」變成「人機翻譯者」。什麼叫人機翻譯者？就是你能跟工程團隊用同一種語言對話，理解技術的限制在哪裡，同時也能把商業需求翻譯成工程師聽得懂的規格。

你們上完這門課之後，當工程師跟你講 API、講 prompt engineering、講 token limit，你不會一臉問號。你不需要比他們厲害，但你要能**接住那個對話**。

不被術語嚇到，也不被忽悠。這兩個同樣重要。

[停頓，語氣放緩]

---

所以我再強調一次——

[看向觀眾]

你們**不是** CS 學生。我不會要求你們寫出完美的、production-ready 的 code。那不是今天的目標。

今天的目標是什麼？是讓你們學會**用 AI 把腦子裡的想法，變成一個可以運行的東西**。

想法在腦子裡，它就只是個想法。但當你能在兩小時內把它變成一個 demo、一個 prototype、一個能讓老闆或投資人看到的東西——那你的說服力就完全不一樣了。

[停頓]

這就是你們需要的超能力。不是寫 code 的能力，是**讓想法落地**的能力。

好，那接下來我們就來看看，今天具體要怎麼做到這件事——
