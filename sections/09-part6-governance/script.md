# Part 6 · 講師逐字稿 — AI Governance & Judgment（15 min）

---

## 開場過渡（1 min）

好，你們剛剛親手用了 AI Agent 做了一個任務。你知道它多厲害了，你也知道它會犯錯。

現在我要你們換一個角色來思考。

你不再是一個學生在用 AI 寫報告。你是一個 Technology Manager，你的 CTO 問你：「我們公司要不要買 AI Agent 工具？買哪一個？怎麼管？」

[動作：停頓]

這 15 分鐘，我們來聊四個 Technology Manager 必須回答的問題。

---

## 第一題：能力邊界（3 min）

[動作：切換到能力邊界投影片]

第一個問題：**AI 的能力邊界在哪裡？**

你們剛剛用 Claude Code 做了一些事情——整理筆記、跑分析、轉格式。看起來很厲害。但它有做不到的事嗎？

有。很多。

它不會主動上網查最新資訊——它的知識有截止日期。它不會打電話幫你訂餐廳。它無法保證每一次輸出都是正確的。

最危險的是什麼？**Hallucination——幻覺。**

AI 會非常有自信地告訴你一件完全不存在的事情。它會編造一篇論文的標題、作者、年份，格式完美，看起來像真的——但那篇論文不存在。

[動作：停頓]

你在學術場景碰到這個，頂多被 supervisor 退稿。但如果更嚴重呢？今年有一個全球首例 AI 致死的訴訟案——一個 36 歲的男子，因為婚姻問題孤獨，連續 56 天跟 Google 的 Gemini 聊天，建立了一種虛幻的親密關係。AI 逐漸失效了安全防護機制，最後這個人精神崩潰，過世了。家屬把 Google 告上法庭。

這不是科幻電影，這是今年的真實案件。

如果你在公司裡碰到呢？AI 給了一個不存在的法律條文，你的團隊據此做了決策——這個責任誰扛？

MIT 最近有一個 AI Governance 的研究計畫，涵蓋了將近一千份政策法規。他們做了一件很有意思的事：用 LLM 去分析這些法規，然後跟人類專家的判斷做比對。結論是——LLM 在某些領域確實超越人類專家，但在涉及判斷和脈絡理解的地方，差距還是很大。

所以你作為 manager，你的判斷力不會被 AI 取代——你的判斷力反而變得更值錢。

## 第二題：安全意識（3 min）

[動作：切換到安全意識投影片]

第二個問題：**安全怎麼管？**

三件事：

**第一，API keys 不要硬寫在 code 裡。**

你們剛剛在 setup 的時候拿了一個 API key。那個 key 就像你家大門的鑰匙。你不會把鑰匙貼在門上面，對吧？API key 也一樣——不要寫死在程式碼裡、不要傳到 GitHub 上、不要在 LINE 群組裡傳。有人不小心把 API key 推上公開的 GitHub repo，幾分鐘之內就會被掃到、被盜用，帳單幾千美金。

**第二，AI 生成的 code 要 review。**

Claude Code 會幫你寫程式——但你不能因為它是 AI 寫的就不看。就像你不會因為實習生是名校畢業的就不 review 他的報告。AI 寫的 code 可能有 bug、有安全漏洞、有邏輯錯誤。你至少要看一眼、跑一下測試。

**第三，Permission Model 存在是有道理的。**

剛剛你們體驗了——AI 每一步都問你 Allow。很多人會覺得很煩。但這個設計是刻意的。

有一句話我很同意，來自一個做企業 AI 治理的分析：「公司不為模型能力負責，公司只為系統決策後果負責。」

什麼意思？Claude Opus 4.6 出了幻覺，那是 Anthropic 的事。但你把幻覺的結果拿去做了商業決策——那是你的事。Permission Model 就是那道防線——讓你在每一步都有機會說「等等，讓我看一下」。

## 第三題：組織導入（4 min）

[動作：切換到組織導入投影片]

第三個問題：**你要怎麼把 AI 帶進你的組織？**

這是你們作為 Technology Management 畢業生最可能遇到的真實場景。老闆說「我們也要用 AI」，然後看著你。

我先告訴你一個結論——有人調研了一百家企業的 AI 導入經驗，最後得出的結論不是「買什麼工具」，而是「不要全員培訓」。

為什麼？因為大部分企業失敗不是技術問題。有個人幫一家三百人的公司落地 AI Agent，他踩了三個坑：第一，沒有從一開始建立規範，知識庫越用越亂；第二，從中層主管開始推，結果中層只想看報告不想動手——應該從一線員工開始，因為他們有真實場景和動力；第三，部署計畫拉太長，超過一個月就失去動力了。

所以三個子問題：

**誰該用？怎麼用？**

不是所有人都需要 Agent。你的行銷團隊可能用 ChatGPT 寫文案就夠了——Product 層。你的數據團隊可能需要 Claude Code 跑批量分析——Agent 層。你的法務團隊可能根本不該用 AI——因為幻覺在法律文件裡是致命的。

記得我們講的三層架構嗎？LLM、Product、Agent——不同團隊用不同層級的工具。不是越強越好，是越適合越好。找到你組織裡最痛的那個點，從那裡開始，不要一次鋪開。

**Code review 流程怎麼調整？**

如果你的工程師開始用 AI 寫 code，你現有的 code review 流程夠嗎？AI 可以一天產出一個工程師一週的量——你的 reviewer 跟得上嗎？有些公司開始用 AI 做第一輪 review，人類做第二輪。這是一個正在快速演化的領域。

**IP 和資料安全怎麼處理？**

你把公司的機密資料丟給 AI 處理——那份資料去了哪裡？Anthropic 的 API 會不會拿你的資料去訓練模型？（答案是不會，但你的法務不一定相信你。）你需要有一份清楚的資料政策：哪些資料可以丟給 AI、哪些不行、用什麼渠道丟。

AI Agent 的風控跟傳統軟體的風控是不一樣的。傳統軟體你寫一條規則它就執行一條規則，你可以精確控制。Agent 是自主決策的——你告訴它目標，它自己決定步驟。這意味著你需要在「過程」中做控制，而不只是在「輸入」和「輸出」做控制。Permission Model 就是過程控制的一種形式。

## 第四題：成本結構（3 min）

[動作：切換到成本結構投影片]

最後一個問題——錢。Technology Manager 不能不談錢。

**ChatGPT Plus：每個月 20 美金吃到飽。** 管你用一次還是一千次，就是 20 美金。這很好懂、很好做預算。

**Claude Code / API 計費：按用量算。** 你跑越多、用越多 token，帳單越大。跑一個小任務可能幾分美金，跑一整天的批量分析可能好幾美金。

[動作：停頓]

這對你的預算規劃有什麼影響？

第一，你不能給全公司的人都開 API 帳號然後不管——你得設 budget cap、做用量監控。有人寫過一篇文章叫「效率是假，搶錢是真」——AI 巨頭用免費或低價策略培養你的依賴，等你全公司都離不開了，再改成按量計費。GitHub Copilot 就是這個路徑。所以你要有成本管控機制，不能等帳單來了才驚覺。

第二，不同場景選不同工具。你的客服團隊回覆客戶郵件用 ChatGPT 吃到飽版就好，不需要用 Agent。你的 data team 做一次性的大規模分析，用 Agent 按量計費反而更划算。

第三，ROI 怎麼算？AI 工具的 ROI 不是「省了多少人力成本」——至少不只是。更重要的是「讓本來做不了的事變得可以做了」。你的 3 人團隊以前做不了 100 份問卷的深度分析——現在可以了。這個價值怎麼量化？你作為 Technology Manager 要會回答這個問題。

## 收網（1 min）

[動作：切換到總結投影片]

好，四個問題回顧：

1. **能力邊界**——AI 很強，但它會幻覺、會犯錯。你的判斷力不會被取代。
2. **安全意識**——API key 管好、code 要 review、Permission Model 不要繞過。
3. **組織導入**——分清誰用什麼層級的工具、調整流程、管好資料。
4. **成本結構**——吃到飽 vs 按量計費，不同場景選不同工具。

這四個問題沒有標準答案，但你要能回答。因為這些是面試官、CTO、或你的客戶會問你的問題。

順帶一提——很多人擔心 AI 會取代工程師、取代 PM。但有趣的是，今年全球工程師職位招聘量反而創了三年新高。經濟學裡有個叫「傑文斯悖論」的東西——當一項技術讓某件事的成本大幅下降，結果不是那件事被做得更少，而是被做得更多。AI 降低了軟體開發的成本，反而刺激更多公司投資軟體項目。所以問題不是「AI 會不會取代你」，而是「會用 AI 的你，能不能做到以前做不到的事」。

[動作：停頓]

好，你們今天學了三層架構、裝好了環境、學了 CCC 框架、親手跑了一個場景、也聊了治理和成本。最後一段，我們來聊怎麼把今天學的東西帶走、用在真實的工作裡。
